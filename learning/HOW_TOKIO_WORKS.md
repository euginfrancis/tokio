## 1. The mental model: four layers

```
┌────────────────────────── 4. PUBLIC API ──────────────────────────────┐
│ spawn  sleep  TcpStream  Mutex  mpsc  select!  fs::read  JoinHandle    │   tokio/src/{task,time,net,sync,io,fs,macros}
└──────────────┬────────────────────────────────────────┬────────────────┘
               │ creates tasks                          │ registers wakers
┌──────────────▼──────────── 3. TASK SYSTEM ────────────┼────────────────┐
│ RawTask = one allocation: Header | Core(future) | Trailer               │   runtime/task/
│ State word (flags + ref-count), vtable, Harness::poll, Waker            │
└──────────────┬────────────────────────────────────────┼────────────────┘
               │ Notified handles go into queues        │
┌──────────────▼──────────── 2. SCHEDULER ──────────────┼────────────────┐
│ current_thread  |  multi_thread: workers, local queues, LIFO slot,      │   runtime/scheduler/
│ inject queue, work stealing, idle/park coordination, blocking pool      │   runtime/blocking/
└──────────────┬────────────────────────────────────────┼────────────────┘
               │ park(timeout) when idle                │ wake() on events
┌──────────────▼──────────── 1. DRIVERS ────────────────▼────────────────┐
│ Time driver (timer wheel) → Process → Signal → I/O driver (mio/epoll)   │   runtime/{time,io,signal,process}/
└─────────────────────────────────────────────────────────────────────────┘
```

**The loop that everything serves:** a scheduler thread pops a task → `poll`s it → the future either finishes or returns `Pending` after leaving its `Waker` with a driver/primitive → when the queues are empty the thread **parks inside the driver** (e.g. `epoll_wait` with a timeout = next timer) → an event fires → the driver calls `wake()` → the task goes back into a queue.

## 2. Startup: `#[tokio::main]` → a running runtime

### `tokio-macros/src/entry.rs` — `main()` and `parse_knobs()`
The attribute macro rewrites your `async fn main() { body }` into a normal `fn main()` whose body is:
```rust
tokio::runtime::Builder::new_multi_thread()   // or new_current_thread() for flavor = "current_thread"
    .enable_all()
    .build()
    .expect("Failed building the Runtime")
    .block_on(body);
```
`#[tokio::test]` (`test()`) does the same but defaults to `current_thread`. `parse_knobs` reads `flavor`, `worker_threads`, `start_paused`, `crate`, `unhandled_panic`.

### `runtime/builder.rs` — `Builder`
- `new_multi_thread()` / `new_current_thread()` → `Builder::new(kind, event_interval = 61)`. All the `.worker_threads()`, `.thread_name()`, `.on_thread_start()`, `.enable_io()`, `.enable_time()` methods (≈60 setters) just fill fields.
- **`build()`** dispatches to `build_threaded_runtime()` or `build_current_thread_runtime()`.

### `build_threaded_runtime()` — step by step
1. `worker_threads = self.worker_threads.unwrap_or_else(num_cpus)`.
2. **`driver::Driver::new(cfg)`** builds the driver *stack* (next section).
3. **`blocking::create_blocking_pool(self, max_blocking_threads + worker_threads, …)`** — note the `+ worker_threads`: **worker threads are themselves blocking-pool threads**.
4. `MultiThread::new(...)` creates `Shared` state (one `Remote` per worker with its steal handle and unparker, the inject queue, `OwnedTasks`, idle tracker) and `Launch` (the list of workers).
5. `launch.launch()` → for each worker: **`runtime::spawn_blocking(move || run(worker))`**. That's how worker threads start.
6. Returns `Runtime { scheduler, handle, blocking_pool }`.

### `runtime/driver.rs` — `Driver::new(cfg)`
```
create_io_stack()     → I/O driver (mio::Poll)  →  wrapped by Signal driver  →  wrapped by Process driver
create_clock()        → Clock (supports pause/advance for tests)
create_time_driver()  → Time driver wraps the whole I/O stack
```
So `Driver.park()` calls **time → process → signal → io**: the time driver computes how long it may sleep, then asks the I/O driver to block in `epoll_wait` for that long. If I/O is disabled, a plain `ParkThread` (mutex + condvar) is used instead.

### `runtime/runtime.rs` — `Runtime::block_on(future)`
- Large futures are boxed (`AutoBox::SHOULD_BOX`) to avoid stack overflows.
- **Multi-thread** (`scheduler/multi_thread/mod.rs: block_on`): `context::enter_runtime(handle, true, |blocking| blocking.block_on(future))`. The `block_on` future runs **on your calling thread, not on a worker**. `CachedParkThread::block_on` (`runtime/park.rs`) is the simplest executor in the codebase:
  ```rust
  let waker = self.waker()?;               // waking = unpark this thread
  loop {
      if let Ready(v) = coop::budget(|| f.as_mut().poll(&mut cx)) { return Ok(v); }
      self.park();                          // sleep on a condvar until woken
  }
  ```
- **Current-thread**: see [§7](#7-the-current-thread-scheduler) — the calling thread *becomes* the scheduler.

### `runtime/context/runtime.rs` — `enter_runtime(handle, allow_block_in_place, f)`
Marks the thread as "inside a runtime", installs the handle as current (so `tokio::spawn` works), seeds the thread's RNG from the runtime's seed generator, runs `f`, and restores everything via a guard on exit. If the thread is **already** in a runtime it panics with the famous *"Cannot start a runtime from within a runtime"*.

## 3. The thread-local `CONTEXT`

`runtime/context.rs` defines one `thread_local!` struct that many functions consult:

| Field | Used by | Purpose |
|---|---|---|
| `current: HandleCell` | `with_current()` → `tokio::spawn`, `sleep`, `TcpStream::connect` | "Which runtime am I in?" — this is why you never pass a runtime handle around |
| `scheduler: Scoped<scheduler::Context>` | `with_scheduler()` → `schedule_task` | "Am I a worker thread of this runtime, and do I hold a core?" |
| `runtime: Cell<EnterRuntime>` | `enter_runtime`, `block_in_place` | Prevents nested `block_on` |
| `budget: Cell<coop::Budget>` | `coop::budget`, `poll_proceed` | Cooperative scheduling budget ([§12](#12-cooperative-budgeting-and-yield_now)) |
| `rng: Cell<Option<FastRand>>` | `thread_rng_n()` | `select!` fairness, blocking-pool sharding |
| `current_task_id` | `task::id()` | Current task id |

Key functions: `with_current(f)` (`context/current.rs`) returns `Err(TryCurrentError)` outside a runtime — that's the panic *"there is no reactor running, must be called from the context of a Tokio 1.x runtime"*. `defer(waker)` queues a waker to be woken after the current task yields (used by `yield_now`).

## 4. Spawning a task

```
tokio::spawn(fut)                                   task/spawn.rs
 └ spawn_inner(fut, meta)
    ├ id = task::Id::next()                         runtime/task/id.rs   (global AtomicU64 fetch_add)
    └ context::with_current(|h| h.spawn(fut, id))   runtime/context/current.rs
       └ scheduler::Handle::spawn                   runtime/scheduler/mod.rs   (match CurrentThread | MultiThread)
          └ multi_thread::Handle::spawn → bind_new_task
             ├ shared.owned.bind(fut, handle, id)   runtime/task/list.rs   (OwnedTasks)
             │  ├ new_task()  → RawTask::new()      runtime/task/{mod,raw}.rs   ONE heap allocation
             │  └ bind_inner(): set owner_id, lock shard, if closed → shutdown task, else push
             ├ task_hooks.spawn(meta)               on_task_spawn callback (unstable)
             └ schedule_option_task_without_yield(notified) → schedule_task(task, false)
```

### `bind_new_task` / `OwnedTasks::bind` / `bind_inner`
`new_task` returns three handles to the same allocation: `Task` (owned by the runtime's `OwnedTasks` list), `Notified` (permission to run it once), `JoinHandle` (returned to you). That's why the initial ref-count is 3 (`INITIAL_STATE = 3 * REF_ONE | JOIN_INTEREST | NOTIFIED`).
`bind_inner` locks only **one shard** of the `ShardedList` (chosen by task id) and checks the `closed` flag *under that lock* — this is what makes "spawn during shutdown" safe ([§16](#16-shutdown)).

### `worker.rs: Handle::schedule_task(task, is_yield)` — where does a new task go?
```rust
with_current(|maybe_cx| {
    if this thread is a worker of *this* runtime and still holds its core {
        self.schedule_local(core, task, is_yield);       // fast path, no locks
        return;
    }
    self.push_remote_task(task);    // inject queue (mutex)
    self.notify_parked_remote();    // wake one sleeping worker
})
```

### `schedule_local(core, task, is_yield)`
- If `is_yield` or the LIFO slot is disabled → `run_queue.push_back_or_overflow(task)` and notify.
- Otherwise → put `task` in the **LIFO slot**; the previous LIFO occupant (if any) is moved to the back of the run queue. Only notify other workers if something was displaced (new work is now visible to stealers).
- `push_back_or_overflow` moves **half the local queue** to the inject queue if it's full ([DSA guide A2](./DSA_IN_TOKIO.md)).
- `notify_parked_local()` asks `Idle::worker_to_notify()` for a sleeping worker index — returns `None` if some worker is already searching (avoids thundering herd) — then `remotes[i].unpark.unpark(driver)`.

## 5. Inside a task: memory, state, vtable

Files: `runtime/task/{core,raw,state,harness,waker,join,abort,list}.rs`.

### Memory layout (`core.rs`)
```rust
#[repr(C)]
struct Cell<T: Future, S> {
    header: Header,     // state: AtomicUsize, queue_next, vtable: &'static Vtable, owner_id, …
    core: Core<T, S>,   // scheduler handle S, task_id, stage: Running(T) | Finished(Result<T::Output>) | Consumed
    trailer: Trailer,   // owned list pointers, join waker, hooks
}
```
`RawTask` is just `NonNull<Header>`. Everything else is reached through the **vtable** (`raw.rs`):

| Vtable fn | Implemented by | Called when |
|---|---|---|
| `poll` | `Harness::poll` | A worker runs the task |
| `schedule` | `Harness::schedule` → `S::schedule` | A waker fires |
| `dealloc` | `Harness::dealloc` | Ref-count hits 0 |
| `try_read_output` | `Harness::try_read_output` | `JoinHandle::poll` |
| `drop_join_handle_slow` | … | `JoinHandle` dropped while task still alive |
| `drop_abort_handle`, `shutdown` | … | Abort / runtime shutdown |
| `trailer_offset`, `scheduler_offset`, `id_offset` | consts | Find fields without knowing `T` |

### The state word (`state.rs`)
`RUNNING | COMPLETE | NOTIFIED | JOIN_INTEREST | JOIN_WAKER | CANCELLED | ref-count…` in one `AtomicUsize`. Every `transition_*` function is a CAS loop that returns an enum telling the caller what to do next:

| Function | From → to | Returns |
|---|---|---|
| `transition_to_running()` | NOTIFIED → RUNNING | `Success` / `Cancelled` / `Failed` (already running/complete) / `Dealloc` |
| `transition_to_idle()` | RUNNING → idle | `Ok` / `OkNotified` (woken during poll → reschedule) / `OkDealloc` / `Cancelled` |
| `transition_to_complete()` | RUNNING → COMPLETE | snapshot (is anyone waiting on `JoinHandle`?) |
| `transition_to_notified_by_val/by_ref()` | idle → NOTIFIED | `Submit` (schedule it) / `DoNothing` (already notified or running) / `Dealloc` |
| `transition_to_notified_and_cancel()` | set CANCELLED + NOTIFIED | used by `abort()` |
| `transition_to_shutdown()` | grab RUNNING to cancel | used at runtime shutdown |
| `ref_inc()` / `ref_dec()` | ±`REF_ONE` | `ref_dec` returns true if last ref |

### `harness.rs: Harness::poll()` → `poll_inner()` — running your future
```
poll_inner():
  match state.transition_to_running():
    Success:
      cx = Context::from_waker(waker_ref(header))     // the Waker *is* the task pointer
      res = poll_future(core, cx)                     // ↓
      if Ready → return Complete
      match state.transition_to_idle():
        Ok          → Done          (wait for a wake)
        OkNotified  → Notified      (woken while running: reschedule via yield_now)
        OkDealloc   → Dealloc
        Cancelled   → cancel_task(); Complete
    Cancelled → cancel_task(); Complete
    Failed    → Done
    Dealloc   → Dealloc
```
`poll()` then acts on the result: `Notified` → `scheduler.yield_now(task)` (back of the queue), `Complete` → `complete()`, `Dealloc` → `dealloc()`.

### `poll_future(core, cx)`
Wraps `core.poll(cx)` in **`panic::catch_unwind`**. If your future panics, a drop-guard drops the future *inside* the catch, and the panic becomes `JoinError::panic(id, payload)` stored as the task output. That's why a panicking task doesn't crash the worker thread.

### `complete()`
1. `transition_to_complete()`.
2. If nobody holds a `JoinHandle` → drop the output immediately. Else if the `JoinHandle` registered a waker → `trailer.wake_join()`.
3. Run `on_task_terminate` hook.
4. `release()` → `scheduler.release(task)` removes it from `OwnedTasks` (returns the list's reference).
5. Drop 1 or 2 ref-counts; dealloc if zero.

### `JoinHandle::poll` (`join.rs`)
`coop::poll_proceed` (awaiting a JoinHandle consumes budget) → `raw.try_read_output(&mut ret, waker)` → `can_read_output()`: if `COMPLETE`, take the output (`Stage::Consumed`); otherwise store the waker in the trailer using the `JOIN_WAKER` bit as an access lock.
`JoinHandle::abort()` → `remote_abort()` → sets CANCELLED+NOTIFIED and schedules the task so **the runtime thread** drops the future (needed for `!Send` tasks).

## 6. The worker loop (multi-thread scheduler)

File: `runtime/scheduler/multi_thread/worker.rs`.

### `run(worker)` — thread entry point
Takes the worker's `Core` (if another thread already has it — possible after `block_in_place` — just return), records the thread id for metrics, then `enter_runtime` + `set_scheduler(Context { worker, core: RefCell, defer })` and calls `cx.run(core)`.

### `Context::run(core)` — the main loop
```rust
while !core.is_shutdown {
    core.tick();                                  // tick += 1
    core = self.maintenance(core);                // every 61 ticks: poll drivers without sleeping
    if let Some(task) = core.next_task(&worker) { core = self.run_task(task, core)?; continue; }
    if let Some(task) = core.steal_work(&worker) { core = self.run_task(task, core)?; }
    else { core = if !self.defer.is_empty() { self.park_yield(core) } else { self.park(core) }; }
}
core.pre_shutdown(&worker);        // cancel all tasks in my OwnedTasks shards
worker.handle.shutdown_core(core); // hand the core to the shutdown collector
```

| Function | What it does |
|---|---|
| `maintenance()` | If `tick % event_interval (61) == 0`: `park_yield` (poll I/O + timers with zero timeout so I/O isn't starved by a busy queue), then `Core::maintenance` — submit metrics, check `inject.is_closed()` → `is_shutdown`, check task-dump requests. |
| `Core::next_task()` | Every `global_queue_interval` ticks (self-tuned, [DSA A3](./DSA_IN_TOKIO.md)) check the **inject queue first** (fairness for remote spawns). Otherwise: LIFO slot → local queue; if both empty, grab a **batch** from the inject queue: `n = min(inject.len() / num_workers + 1, free_slots, capacity/2)` — each worker takes its fair share. |
| `next_local_task()` | `lifo_slot.take().or_else(|| run_queue.pop())` |
| `steal_work()` | Only if `transition_to_searching()` allows it (fewer than half the workers searching). Random start index, try each other worker's `steal.steal_into(&mut run_queue)` (takes ⌈n/2⌉), finally the inject queue. |
| `run_task(task, core)` | See below. |
| `transition_from_searching()` | When a searching worker finds work, it stops searching; if it was the **last** searcher it wakes another worker to keep searching (so new work keeps getting picked up). |

### `run_task(task, core)` — polling and the LIFO loop
1. `owned.assert_owner(task)` → `LocalNotified` (permission to poll on this thread).
2. `transition_from_searching()`.
3. Put `core` back into `self.core` (the RefCell) — **the task might steal it** via `block_in_place`.
4. Inside **one** `coop::budget(|| …)` (128 units):
   - `task.run()` → vtable `poll` → `Harness::poll` ([§5](#5-inside-a-task-memory-state-vtable)).
   - Loop: if the core was taken (block_in_place) → `Break` (this thread stops being a worker). If the LIFO slot has a task and budget remains and fewer than `MAX_LIFO_POLLS_PER_TICK = 3` LIFO polls happened → run it immediately; else push it to the run queue and return.

### `park(core)` / `park_internal(core, timeout)`
- `before_park` hook → `transition_to_parked()`: if there's still local work, don't park. Otherwise register as idle with `Idle`; if this was the **last searcher**, call `notify_if_work_pending()` (any queue non-empty → wake someone) to avoid a lost task.
- Loop: `park_internal(core, None)` → `core.maintenance()` → `transition_from_parked()` (did someone actually unpark *me*? spurious wake-ups loop).
- `park_internal`: takes the `Parker` out of the core, **puts the core into the RefCell** (so drivers waking tasks during the park can `schedule_local` straight into this core!), calls `park.park(driver)` or `park_timeout`, then `defer.wake()` (tasks that called `yield_now`), and if more than one task is now queued, `notify_parked_local()` to share the work.

## 7. The current-thread scheduler

File: `runtime/scheduler/current_thread/mod.rs`. Same concepts, one thread, no stealing.

- `CurrentThread::block_on(handle, future)`: tries `take_core()`. The thread that gets the core runs `CoreGuard::block_on`. If another thread is already driving the runtime, this thread waits on `notify.notified()` **or** its own future completing — whichever comes first.
- **`CoreGuard::block_on(future)`** — the whole scheduler in ~60 lines:
  ```
  'outer: loop {
      if handle.reset_woken() { poll the block_on future (with budget); if Ready → return }
      for _ in 0..event_interval (61) {
          core.tick();
          match core.next_task(handle) {
              Some(task) => core = context.run_task(task, core),
              None => { core = if has_pending_work { park_yield } else { park }; continue 'outer; }
          }
      }
      core = context.park_yield(core, handle);   // poll I/O + timers without sleeping
  }
  ```
  The `block_on` future has its own waker (`Handle::waker_ref`) that sets a `woken` flag, so it's only re-polled when actually woken.
- `next_task()`: every `global_queue_interval` ticks prefer the inject queue, otherwise local `VecDeque` first.
- `Handle::schedule(task)`: if called on the runtime's own thread with the core available → `core.push_task()` (a `VecDeque`); otherwise → `inject.push()` + `driver.unpark()` (wake the thread out of `epoll_wait`).

## 8. Parking: how idle threads sleep and wake

File: `runtime/scheduler/multi_thread/park.rs`. States: `EMPTY`, `PARKED_CONDVAR`, `PARKED_DRIVER`, `NOTIFIED`.

### `Inner::park(handle)`
```rust
if state.compare_exchange(NOTIFIED, EMPTY).is_ok() { return; }    // a wake arrived early: don't sleep
if let Some(mut driver) = shared.driver.try_lock() {
    park_driver(&mut driver, handle, None)    // I'm the one thread sleeping in epoll_wait
} else {
    park_condvar(None)                        // someone else has the driver: sleep on a condvar
}
```
**Only one worker at a time holds the driver.** It sleeps in the OS (`epoll_wait`), so it's the one woken by I/O and timers. Other idle workers sleep on their condvars.

### `Inner::unpark(driver)`
```rust
match state.swap(NOTIFIED) {                   // swap, not CAS: always publish a release
    EMPTY | NOTIFIED => {}                     // it will see NOTIFIED next time it parks
    PARKED_CONDVAR   => unpark_condvar(),      // lock mutex, notify_one
    PARKED_DRIVER    => driver.unpark(),       // write to mio's Waker → epoll_wait returns (TOKEN_WAKEUP)
}
```

## 9. Waking a task

File: `runtime/task/waker.rs`. A task's `Waker` is a `RawWaker` whose data pointer is the task's `Header` and whose vtable is:
```rust
static WAKER_VTABLE: RawWakerVTable = RawWakerVTable::new(clone_waker, wake_by_val, wake_by_ref, drop_waker);
```
- `clone_waker` → `header.state.ref_inc()` (a waker is just another ref-count).
- `drop_waker` → `ref_dec()`, dealloc if last.
- `wake_by_val` → `Harness::wake_by_val()`:
  ```rust
  match state.transition_to_notified_by_val() {
      Submit    => { self.schedule(); self.drop_reference(); }  // vtable.schedule → Handle::schedule_task
      Dealloc   => self.dealloc(),
      DoNothing => {}            // already NOTIFIED or RUNNING (RUNNING: poll_inner will see NOTIFIED and reschedule)
  }
  ```
So `waker.wake()` from **any thread** ends up in `schedule_task` ([§4](#4-spawning-a-task)): local push if on a worker, inject + unpark otherwise.

## 10. I/O: from `socket.read().await` to epoll and back

### Registration: `TcpListener::bind` / `TcpStream::connect`
→ `PollEvented::new(mio_socket)` (`io/poll_evented.rs`) → `Registration::new_with_interest_and_handle` (`runtime/io/registration.rs`) → **`io::Handle::add_source()`** (`runtime/io/driver.rs`):
```rust
let scheduled_io = self.registrations.allocate(..)?;   // Arc<ScheduledIo>, kept in a linked list
let token = scheduled_io.token();                       // token = the ScheduledIo's ADDRESS
self.registry.register(source, token, interest.to_mio())?;   // epoll_ctl(ADD), edge-triggered
```

### `ScheduledIo` (`runtime/io/scheduled_io.rs`) — one per socket, cache-line padded
- `readiness: AtomicUsize` = `READINESS` (16 bits: readable, writable, read_closed, …) | `TICK` (15 bits) | `SHUTDOWN` (1 bit), packed with `util::bit::Pack`.
- `waiters: Mutex<Waiters>` = a `reader` waker slot, a `writer` waker slot, and an intrusive list for `readable()`/`ready()` futures.

### Reading: `AsyncRead for TcpStream` → `PollEvented::poll_read(cx, buf)`
```rust
loop {
    let evt = ready!(self.registration.poll_read_ready(cx))?;   // ① wait until readable
    match self.io.read(buf) {                                    // ② real non-blocking read(2)
        Ok(n) => {
            if 0 < n && n < len { self.registration.clear_readiness(evt); }  // ③ short read ⇒ socket drained (epoll/kqueue)
            return Ready(Ok(()));
        }
        Err(WouldBlock) => self.registration.clear_readiness(evt),   // ④ readiness was stale: clear and loop
        Err(e) => return Ready(Err(e)),
    }
}
```
③ saves a pointless extra `read()` → `EAGAIN` round trip on edge-triggered selectors.

### `Registration::poll_ready(cx, direction)` → `ScheduledIo::poll_readiness(cx, direction)`
1. Budget check (`coop::poll_proceed`).
2. Load `readiness`; if the requested bits are set (or shut down) → `Ready(ReadyEvent { tick, ready })`.
3. Else lock `waiters`, store `cx.waker()` in the `reader`/`writer` slot, **re-check readiness** (an event may have landed in between), return `Pending`.

### `ScheduledIo::clear_readiness(event)` → `set_readiness(Tick::Clear(event.tick), |r| r - event.ready)`
The **tick** is the ABA guard: the driver increments the tick on every new event. If the tick changed since you observed readiness, a *newer* event arrived, and your stale `WouldBlock` must **not** erase it — `set_readiness` returns without changing anything.

### The driver side: `io::Driver::turn(handle, max_wait)` (`runtime/io/driver.rs`)
Called from `park`/`park_timeout`:
```rust
self.poll.poll(events, max_wait)        // epoll_wait / kqueue / IOCP — the thread sleeps HERE
for event in events {
    match event.token() {
        TOKEN_WAKEUP => {}                         // unpark() woke us
        TOKEN_SIGNAL => self.signal_ready = true,
        token => {
            let io: &ScheduledIo = unsafe { &*ptr_from(token) };       // token → pointer, no lookup table
            io.set_readiness(Tick::Set, |curr| curr | Ready::from_mio(event));   // tick += 1
            io.wake(ready);
        }
    }
}
```

### `ScheduledIo::wake(ready)`
Collects matching wakers (reader slot, writer slot, list waiters whose interest is satisfied) into a **`WakeList`** (32 slots on the stack), **drops the lock**, then `wake_all()`; repeats if more than 32. Waking outside the lock avoids deadlocks and contention.

### `TcpListener::accept()` (`net/tcp/listener.rs`)
```rust
let (mio, addr) = self.io.registration().async_io(Interest::READABLE, || self.io.accept()).await?;
let stream = TcpStream::new_accepted(mio)?;    // registers the new socket with the driver
```
`Registration::async_io` is the `async` twin of `poll_io`: `readiness(interest).await` → `poll_proceed` → try `f()` → on `WouldBlock` `clear_readiness` and loop. Most networking methods (`send_to`, `recv_from`, `peek`, …) are thin wrappers over `async_io`/`poll_io` — which is why `net` is 2× docs vs code.

## 11. Time: `sleep`, the timer wheel and the time driver

### `time::sleep(duration)` (`time/sleep.rs`)
`deadline = Instant::now() + duration` → `Sleep::new_timeout(deadline)`. **No timer is registered yet** — `Sleep` holds `timer: None`.

### `Sleep::poll` → `poll_elapsed(cx)`
1. `coop::poll_proceed`.
2. First poll: convert the deadline to a tick (`time_source.deadline_to_tick`, 1 tick = 1 ms, rounded **up**), create a `TimerEntry` and `init()` it → `Handle::reregister`.
3. `TimerEntry::poll_elapsed(cx)` → `state.poll(waker)`: if fired → `Ready`, else store the waker → `Pending`.

### `TimerEntry::reset(deadline)` (used by `Sleep::reset`, `timeout`, `interval`)
```rust
if self.inner.extend_expiration(deadline).is_ok() { return; }   // lock-free fast path!
handle.reregister(...)                                            // slow path: take driver lock
```
**Lazy rescheduling** (explained at the top of `runtime/time/entry.rs`): if the new deadline is *later* than the registered one, just update an atomic; the timer stays in its old wheel slot. When the wheel reaches that slot, the driver sees the true deadline is later and re-inserts it. Resetting an idle-timeout on every packet therefore costs one atomic store.

### `time::Handle::reregister(unpark, new_tick, entry)` (`runtime/time/mod.rs`)
Under the driver lock: remove from the wheel if present → if driver is shut down fire with `Err(shutdown)` → else `set_expiration`, `wheel.insert(entry)`:
- `Ok(when)`: if `when` is earlier than `next_wake` → **`unpark()` the driver** so the sleeping thread recomputes its timeout.
- `Err(Elapsed)`: deadline already passed → fire immediately.
The waker returned by `fire` is woken *after* the lock is released.

### `time::Driver::park_internal(handle, limit)`
```rust
let next_wake = lock.wheel.next_expiration_time();         // O(1) via occupied bitmaps
match next_wake {
    Some(when) => park the I/O driver for min(when - now, limit)   // or park_timeout(0) if overdue
    None       => park indefinitely (or for `limit`)
}
handle.process(clock);       // fire everything due
```

### `process_at_time(now)`
Locks the wheel; `while let Some(entry) = wheel.poll(now)` → `entry.fire(Ok(()))` → push waker into a `WakeList`; when 32 wakers accumulate, **unlock, wake them, relock**. Finally record `next_wake = wheel.poll_at()`.

### `Wheel::insert` / `poll` / `level_for` / `next_expiration`
See the [DSA guide D7, A5–A7](./DSA_IN_TOKIO.md) and the runnable version in [`dsa-exercises/src/wheel.rs`](./dsa-exercises/src/wheel.rs).

### Dropping a `Sleep`
`Drop for TimerEntry` → `cancel()` → `clear_entry()` takes the driver lock (also serving as the acquire/release fence the comment explains) and unlinks it from the wheel in O(1).

### Test time: `time::pause()` / `advance()`
`Clock` (`time/clock.rs`) can be frozen; when all tasks are idle and time is paused, the driver **auto-advances** to the next timer instead of sleeping — tests with 1-hour timeouts run instantly.

## 12. Cooperative budgeting and `yield_now`

File: `task/coop/mod.rs`.
- `coop::budget(f)`: sets the thread's budget to **128** (`Budget::initial()`), runs `f` (one task poll, including LIFO follow-ups), restores the old budget.
- **`poll_proceed(cx)`** — called by the budget-aware Tokio resources before doing work (mpsc/oneshot receive, semaphore acquire, I/O readiness, `Sleep`, `JoinHandle`, `io::copy`, process wait, `consume_budget`; it is also public as `tokio::task::coop::poll_proceed`). Not literally every resource: e.g. plain `Notify` or `std`-only code never charge the budget:
  ```rust
  if budget.decrement().success { Ready(RestoreOnPending) }
  else { register_waker(cx); Pending }       // out of budget: register_waker = context::defer(cx.waker()) — the task is woken only AFTER the scheduler has run other tasks and polled the driver (not immediately)
  ```
  `RestoreOnPending` gives the unit back if the operation ends up `Pending` (no progress → no charge); call `.made_progress()` to keep the charge.
- `unconstrained(fut)` disables the budget; `coop::stop()` is used by `block_in_place`.

`task::yield_now()` (`task/yield_now.rs`): first poll calls `context::defer(cx.waker())` and returns `Pending`; the worker wakes deferred wakers **after** it has looked at other work (in `park_internal` / `park_yield`), so a yielding task goes to the back of the line instead of being re-polled immediately.

## 13. Synchronization: Semaphore → Mutex, mpsc, oneshot, Notify

### The building block: `batch_semaphore::Semaphore` (`sync/batch_semaphore.rs`)
State: `permits: AtomicUsize` (`available << 1 | CLOSED`) + `waiters: Mutex<Waitlist>` (intrusive list, new waiters pushed at the front, served from the back = FIFO).

**`acquire(n)`** returns an `Acquire` future containing an intrusive `Waiter { state: needed_permits, waker, pointers }`. `Acquire::poll` → **`poll_acquire(cx, n, node, queued)`**:
1. CAS loop on `permits`: take as many as available (possibly fewer than needed). If not all, grab the waiters lock *before* the CAS so nobody can release in between.
2. Got everything and wasn't queued → `Ready(Ok)` — the **lock-free fast path**.
3. Otherwise `node.assign_permits(&mut acquired)`; store the waker; if not queued, push the node into the waitlist → `Pending`.
4. Fairness: while anyone waits, released permits go to waiters first, so `permits` stays at 0 and newcomers can't jump the queue.

**`release(n)`** → **`add_permits_locked(rem, waiters)`**: while permits remain, look at the **oldest** waiter (`queue.last()`), `assign_permits` (partial fills allowed); fully satisfied waiters are popped and their wakers pushed to a `WakeList`; leftovers go back to the atomic counter. Wakers are called after unlocking.

**`Drop for Acquire`**: if a queued waiter is dropped (e.g. `select!` cancelled it), remove the node from the list and **give back any partially assigned permits** — cancellation safety.

### `Mutex<T>` (`sync/mutex.rs`)
```rust
pub async fn lock(&self) -> MutexGuard<'_, T> { self.acquire().await; MutexGuard { lock: self } }
async fn acquire(&self) { self.s.acquire(1).await.unwrap_or_else(|_| unreachable!()) }
impl Drop for MutexGuard<'_, T> { fn drop(&mut self) { self.lock.s.release(1); } }
```
That's the whole lock. `try_lock` → `s.try_acquire(1)`; `lock_owned` returns an `OwnedMutexGuard` holding an `Arc<Mutex>` (so it's `'static`); `blocking_lock` runs `block_on` on a temporary parker. `RwLock` = semaphore with `MAX_READS` permits (reader 1, writer all); `Semaphore` (public) wraps it directly.

### `mpsc` (`sync/mpsc/{bounded,chan,list,block}.rs`)
**Send (bounded):**
```
Sender::send(value).await
 └ reserve().await → reserve_inner(1) → chan.semaphore.0.acquire(1).await     (capacity = semaphore permits)
 └ Permit::send(value) → chan::Tx::send(value)
     └ Chan::send: self.tx.push(value); self.rx_waker.wake();
         └ list::Tx::push: slot = tail_position.fetch_add(1)   // claim a slot, lock-free
                           block = find_block(slot)            // walk/allocate 32-slot blocks
                           block.write(slot, value)            // store + set ready bit
```
**Receive:** `Receiver::recv().await` → `chan::Rx::recv(cx)`:
```rust
let coop = ready!(poll_proceed(cx));
try_recv!();                                   // list.pop(): read next slot if its ready bit is set
self.inner.rx_waker.register_by_ref(cx.waker());   // AtomicWaker (DSA A13)
try_recv!();                                   // re-check: a send may have raced with registration
if rx_closed && semaphore.is_idle() { Ready(None) } else { Pending }
```
On a successful pop: `semaphore.add_permit()` frees capacity, which wakes a blocked sender. **Unbounded** channels use an `AtomicUsize` counter instead of a semaphore. `Receiver::drop` closes the channel and drains remaining values.

### `oneshot` (`sync/oneshot.rs`)
One allocation with `value: UnsafeCell<Option<T>>`, `rx_task`, `tx_task`, and a state word `RX_TASK_SET | VALUE_SENT | CLOSED | TX_TASK_SET`. `Sender::send(t)`: write the value, then `complete()` sets `VALUE_SENT` via CAS; if the receiver was closed, take the value back and return `Err(t)`; if `RX_TASK_SET`, wake the receiver. `Receiver::poll` → `poll_recv`: check `VALUE_SENT` → take; else register waker (`RX_TASK_SET`) and re-check.

### `Notify` (`sync/notify.rs`)
State word: `EMPTY | WAITING | NOTIFIED` + a counter of `notify_waiters` calls.
- `notified()` returns a `Notified` future (intrusive waiter node). `poll_notified`: if state is `NOTIFIED`, consume it → `Ready`; else lock, push node at the front, set `WAITING`, store waker → `Pending`.
- **`notify_one()`** → `notify_locked()`: if `EMPTY`/`NOTIFIED` → set `NOTIFIED` (store a **permit** for the next `notified()`); if `WAITING` → pop the oldest waiter (`pop_back`), mark it `Notification::One`, return its waker; set `EMPTY` if no waiters remain.
- `notify_waiters()`: wakes all *current* waiters (bumps the call counter so futures created later don't see it), no permit stored. Uses a guarded list so it can release the lock between batches of 32.

## 14. Blocking work: `spawn_blocking`, `fs`, `block_in_place`

### `task::spawn_blocking(f)` → `runtime/blocking/pool.rs`
`Spawner::spawn_blocking` wraps `f` in a `BlockingTask` future (polls once, runs `f`, returns) and creates a normal task with a `BlockingSchedule` → `spawn_task(task)`:
```rust
let mut locked = self.mutex.lock();
if shutdown { task.shutdown(); return Err(ShuttingDown); }
locked.queue.push_back(task);
if no idle threads { spawn_thread() (up to max_blocking_threads = 512 by default) }
else { locked.num_notify += 1; condvar.notify_one(); }
```
**Thread loop `run_worker(keep_alive)`:** pop & run tasks (unlocking around `task.run()`); when empty, `condvar.wait_timeout(keep_alive = 10 s)`; on `num_notify` → run more; on timeout → exit the thread; on shutdown → run "mandatory" tasks, drop others.
(Opt-in alternative: the sharded queue, [DSA D14](./DSA_IN_TOKIO.md).)

### `fs::read(path)` and most of `fs` (`fs/mod.rs: asyncify`)
```rust
pub(crate) async fn asyncify<F, T>(f: F) -> io::Result<T> {
    match spawn_blocking(f).await { Ok(res) => res, Err(_) => Err(io::Error::other("background task failed")) }
}
```
`fs::read` = `asyncify(move || std::fs::read(path))` (or io_uring `statx`+`read` on Linux with `tokio_unstable` + `io-uring`). `fs::File` keeps an internal buffer and an in-flight blocking operation so `AsyncRead`/`AsyncWrite` can be implemented on top of blocking calls.

### `task::block_in_place(f)` → `multi_thread/worker.rs`
`maybe_move_runtime()`: take this worker's `Core` out of the context, move its LIFO task to the run queue, store the core back in `worker.core`, and **`spawn_blocking(move || run(worker))`** — a *new* thread becomes this worker. The current thread runs `f()` (outside the runtime context, budget stopped). On return, the `Reset` guard tries to take the core back; if the new thread already has it, `run_task` sees the core missing and this thread stops being a worker.

## 15. Macros: `select!`

`macros/select.rs` expands (simplified) to:
```rust
let mut futures = (fut0, fut1, ...);           // all branch futures, pinned in place
let mut disabled: u64 = 0;                      // bitmask of finished / non-matching branches
poll_fn(|cx| {
    ready!(poll_budget_available(cx));          // don't loop forever on an exhausted budget
    let start = thread_rng_n(BRANCHES);         // random start → fairness ("biased;" uses 0)
    for i in 0..BRANCHES {
        let branch = (start + i) % BRANCHES;
        if disabled & (1 << branch) != 0 { continue; }
        match poll(futures.branch) {
            Pending => { is_pending = true; continue; }
            Ready(out) => {
                disabled |= 1 << branch;
                if !matches!(out, <pattern>) { continue; }   // pattern mismatch disables the branch
                return Ready(Out::_branch(out));
            }
        }
    }
    if is_pending { Pending } else { Ready(Out::Disabled) }   // all disabled → `else` branch
}).await
```
Then a `match` runs the winning branch's handler. **Losing futures are dropped** when `select!` returns — which is why the docs list "cancel safety" for every method. `join!`/`try_join!` (`macros/join.rs`) poll all futures in rotating order and wait until all are done.

## 16. Shutdown

`drop(runtime)` or `runtime.shutdown_timeout(d)`:
1. `Runtime::drop` → `MultiThread::shutdown` → `Handle::shutdown()` → **`close()`**: `inject.close()` (set closed bit) then `notify_all()` unparks every worker.
2. Each worker's `maintenance()` sees `inject.is_closed()` → `core.is_shutdown = true` → leaves `Context::run`.
3. `Core::pre_shutdown()` → `owned.close_and_shutdown_all(random_start)`: closes `OwnedTasks` (so `bind_inner` rejects new spawns) and calls `task.shutdown()` on every task in its shards → futures dropped, `JoinHandle`s get `JoinError::Cancelled`.
4. `Handle::shutdown_core(core)`: push core into `shared.shutdown_cores`; **the last worker** drains every core's local queue, parks drivers for shutdown (`Core::shutdown` → `park.shutdown(driver)`: I/O driver sets the `SHUTDOWN` bit on every `ScheduledIo` and wakes its waiters, so pending reads return errors; time driver sets `is_shutdown` and runs `process_at_time(u64::MAX)`, firing every remaining timer so its task wakes up), and empties the inject queue.
5. `BlockingPool::drop` → `shutdown(None)`: set shutdown, `notify_all` the condvar, **wait for all blocking threads** (or `timeout` with `shutdown_timeout`). This is why a `spawn_blocking` task that never returns makes `drop(runtime)` hang.

The comment at the top of `worker.rs` proves why both the inject queue and `OwnedTasks` need a closed bit ([DSA A16](./DSA_IN_TOKIO.md)).

## 18. Recurring patterns (learn these once)

1. **Check → register waker → check again.** Every `poll` that can return `Pending` re-checks after registering (mpsc `recv`, `poll_readiness`, oneshot, Notify). Otherwise an event between the check and the registration would be lost forever.
2. **Collect wakers under the lock, wake after unlocking** (`WakeList`): `ScheduledIo::wake`, `add_permits_locked`, `process_at_time`, `Notify`.
3. **State machines in one atomic word**, transitions as CAS loops returning "what to do next" enums (task `State`, `ScheduledIo` readiness, oneshot, Notify, semaphore permits).
4. **Intrusive nodes inside pinned futures** — waiters don't allocate; `Drop` unlinks them (cancellation safety).
5. **Thin public API, fat internals**: `Mutex::lock` is 3 lines over the semaphore; `TcpListener::accept` is 3 lines over `async_io`.
6. **`cfg_*!` macros** wrap almost every item (`macros/cfg.rs`) — features compile whole modules in or out.
7. **Budget-aware resources call `coop::poll_proceed`** before doing work (channels, semaphore, I/O readiness, timers, `JoinHandle`, …); see [`core/task/10`](./core/task/10-coop-budget.md).
8. **`Send` tasks go anywhere; `!Send` tasks (LocalSet / LocalRuntime) never leave their thread** — hence `remote_abort` scheduling instead of dropping directly.
